# Contributing

Contributions are welcome. No contributor licence agreement. By contributing,
you agree that your contribution is released under 0BSD with the rest of the
project.

## Before opening a pull request

1. Name the real writing failure your change repairs.
2. Show why existing guidance does not already cover it.
3. Add or update a realistic eval when behaviour changes.
4. Preserve medium, speaker, recipient, client authorship, and protected facts.
5. Validate the skill with `skills-ref validate "$(pwd)"`.
6. Keep `SKILL.md` lean; route specialised detail to one focused reference.

## Useful contributions

- a real failure case with private details removed;
- a medium register the current package genuinely misses;
- an eval exposing outcome failure, client overwrite, or mechanism repetition;
- a clearer instruction that removes ambiguity or duplication;
- cross-client installation evidence.

## Please do not add

- phrase banks or catchphrases;
- speaker caricatures;
- generic banned-word lists;
- numerical voice, soul, wit, warmth, or humanity scores;
- surface rules written only to pass one eval;
- copied private messages, client work, or personal details;
- executable code without an objective, repeatable need.

## Review standard

A change should make the skill more truthful, useful, specific, portable, or
protective of authorship. More “pitch.dog-like” is not enough.
